# ft_irc — Расширенный Subject и Условия Проверки

Ниже приведён список требований, дополненный и оформленный в виде единого документа.

---

## 1. Общие требования устойчивости

1. Программа **не должна крашиться** ни при каких условиях.  
2. Нужно проверять **все возвраты системных вызовов** на ошибки.  
3. Обработка ошибок должна быть корректной: закрытие сокетов, освобождение ресурсов, отсутствие segfault.

---

## 2. Makefile и структура проекта

1. Должен быть **Makefile** без лишних релинков.  
2. Обязательные правила:  
   - `$(NAME)`  
   - `all`  
   - `clean`  
   - `fclean`  
   - `re`
3. Имя программы: **ircserv**.  
4. Файлы проекта:  
   - `Makefile`  
   - `*.h`, `*.hpp`  
   - `*.cpp`  
   - `*.tpp`, `*.ipp`  
   - Опциональный конфигурационный файл  
5. Компиляция должна выполняться строго с флагами:
   ```
   c++ -Wall -Wextra -Werror -std=c++98
   ```

---

## 3. Использование языка C++

1. Везде, где возможно, нужно использовать **концепции и возможности C++**, включая:
   - RAII  
   - STL-контейнеры  
   - std::string, std::map, std::vector и др.  
2. **Внешние библиотеки запрещены**, включая Boost.

---

## 4. Аргументы программы

Запуск осуществляется так:

```
./ircserv <port> <password>
```

Где:  
- `port` — порт для входящих подключений  
- `password` — пароль для подключения клиентов

---

## 5. Разрешённые внешние функции

Разрешены **только** следующие функции:

- Всё из C++98  
- `socket`, `close`, `setsockopt`, `getsockname`,  
- `getprotobyname`, `gethostbyname`, `getaddrinfo`, `freeaddrinfo`,  
- `bind`, `connect`, `listen`, `accept`,  
- `htons`, `htonl`, `ntohs`, `ntohl`,  
- `inet_addr`, `inet_ntoa`, `inet_ntop`,  
- `send`, `recv`,  
- `signal`, `sigaction`,  
- `sigemptyset`, `sigfillset`, `sigaddset`, `sigdelset`, `sigismember`,  
- `lseek`, `fstat`, `fcntl`,  
- `poll` или эквивалент: `select`, `kqueue`, `epoll`.

---

## 6. Ограничения и сетевой стек

1. IRC-клиент писать **не нужно**.  
2. Межсерверное взаимодействие **не требуется**.  
3. Вместо `poll()` можно использовать `select()`, `kqueue()` или `epoll()`.  
4. Сервер должен выдерживать **много клиентов**.  
5. **fork запрещён**.  
6. Все операции ввода-вывода должны быть **неблокирующими**.  
7. Должен использоваться **один единственный механизм мультиплексирования** для всех операций:
   - чтение  
   - запись  
   - входящие соединения  
   - события  
8. Работа с сокетами возможна **только через** этот механизм (poll/select/kqueue/epoll).  
9. Все сокеты должны быть переведены в **O_NONBLOCK**.

---

## 7. IRC-логика и протокол

1. Сервер должен обеспечивать корректное подключение IRC-клиента.  
2. Клиент должен иметь возможность установить пароль, никнейм и username.  
3. Должна поддерживаться работа с каналами.  
4. Пользователи должны уметь отправлять приватные сообщения и сообщения в канал.  
5. Должны поддерживаться права оператора канала:
   - `KICK`  
   - `INVITE`  
   - `TOPIC`  
   - `MODE` с флагами `i, t, k, o, l`  
6. Сервер должен корректно собирать команды из нескольких частичных пакетов.  
7. Команды в одном пакете должны парситься корректно и по отдельности.  
8. Плохая команда не должна ломать соединение и/или сервер.

---

## 8. Валидация аргументов

1. Неверное количество аргументов → вывод ошибки и завершение.  
2. Неверный порт → корректная проверка.  
3. Пароль пустой или некорректный → корректная обработка.

---

## 9. Чистота кода

1. Чистая архитектура: классы Server, Client, Channel, CommandHandler и др.  
2. Ясное отделение сетевой логики от логики протокола.  
3. Нет утечек памяти.  
4. Нет бесконечных блокирующих циклов.  
5. Нет "божественных" функций огромного размера.

---

## 10. Итоговые требования проверки

1. make → нет релинков  
2. Сервер запускается без крашей  
3. IRC-клиент подключается без ошибок  
4. JOIN/PRIVMSG/PART работают  
5. Каналы и операторские команды корректны  
6. Многоклиентская работа стабильна  
7. Все системные вызовы проверяются  
8. Вся работа с I/O — только через единый poll/select/kqueue/epoll  
9. Никаких внешних библиотек  
10. Код читаемый и соответствует C++98
